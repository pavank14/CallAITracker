# Personal AI Caller — Phase 4

Phase 4 upgrades the conversation simulator into a voice-enabled AI prototype. It keeps the Phase 3 React dashboard, Node.js API, and SQLite storage, and adds a local Ollama chat endpoint plus browser speech input/output.

## What works in this phase

- AI replies are generated by a local Ollama model instead of rule-based keyword responses.
- Type a caller's message or use microphone speech recognition in a supported browser.
- Speak AI replies aloud with the browser/device speech synthesizer, with a toggle to mute voice output.
- Choose English, Hindi, Marathi, or English + Hindi in Assistant Settings. The chosen language is passed to the model and speech engine.
- End & save a simulation to store one transcript in SQLite and show it in Call History.
- The local AI status panel reports whether Ollama and the configured model are available.

**This is not a live telephone call.** SIM-call routing and live call audio remain a separate later phase.

## Requirements

- Node.js **22.13 or newer** (this project uses Node's built-in `node:sqlite` API).
- npm.
- [Ollama](https://ollama.com/download) installed and running locally.
- A computer with enough memory for the chosen local model. The default model is `qwen2.5:3b` (about 1.9 GB model download; runtime memory use is higher).
- A current Chrome or Edge browser is recommended for microphone speech recognition. If recognition is unsupported or blocked, use the text input. Speech recognition support varies by browser; it may use a browser/cloud service instead of being fully on-device.

## Setup

### 1. Install and download the local model

Install Ollama, then in a terminal run:

```bash
ollama pull qwen2.5:3b
```

Make sure Ollama is running. On systems where it does not start automatically, run `ollama serve` in its own terminal. If the model download is too large for your computer, you can configure a smaller supported model using the `OLLAMA_MODEL` environment variable.

### 2. Install project packages

Open this project folder in VS Code and run:

```bash
npm install
```

### 3. Start the backend

In terminal 1:

```bash
npm run dev:server
```

The API runs at `http://127.0.0.1:3001`. The SQLite database is created at `server/personal-ai-caller.sqlite` on first start.

### 4. Start the website

In terminal 2, from the same project folder:

```bash
npm run dev
```

Open the local URL shown by Vite (usually `http://localhost:5173`).

### 5. Try a voice conversation

1. Open **Conversation simulator / AI voice conversation**.
2. Check the local AI status panel; it should show `Connected · qwen2.5:3b`.
3. Press **Start conversation** to hear the greeting.
4. Tap the microphone and allow microphone access. Speak, then pause; recognized text is sent to the local AI.
5. You can also type a caller message and press Send.
6. Use the speaker toggle to mute/unmute generated speech.
7. Press **End & save** to store the transcript in Call History.

## Configuration

The server reads two optional environment variables:

- `OLLAMA_BASE_URL` — default `http://127.0.0.1:11434`
- `OLLAMA_MODEL` — default `qwen2.5:3b`

PowerShell example (run the backend from this terminal):

```powershell
$env:OLLAMA_MODEL = "qwen2.5:3b"
$env:OLLAMA_BASE_URL = "http://127.0.0.1:11434"
npm run dev:server
```

No paid AI API key is used by this default local setup. The local language model has no per-message API charge, though your computer uses CPU/GPU resources and power. Speech recognition is separate: the browser may send microphone audio to its speech service depending on browser implementation and settings. Avoid sensitive conversations during testing.

## API endpoints added in Phase 4

- `GET /api/ai/status` — reports Ollama reachability and whether the configured model is installed.
- `POST /api/ai/chat` — accepts `{ "message": "...", "language": "English", "history": [] }` and returns a generated reply.

The existing Phase 3 endpoints for calls, saved transcripts, settings, and health remain in place.

## Troubleshooting

- **AI not ready:** make sure Ollama is running, then run `ollama pull qwen2.5:3b` and click refresh in the AI status panel.
- **Model not found:** the backend response shows the model-pull command. If you use a different model, set `OLLAMA_MODEL` before starting the backend.
- **Mic button does not work:** use current Chrome/Edge, allow microphone access, and start recognition with a user click. You can always type instead.
- **No voice is heard:** switch voice output on, check the computer's output volume, and verify that a voice for the selected language is installed.
- **Call not saved:** confirm the API is running in terminal 1 and verify `http://127.0.0.1:3001/api/health` returns `ok: true`.

## Security and scope

The backend binds to `127.0.0.1` for local development. No authentication is added yet; do not expose the development server to the public internet. The browser microphone flow is for the local simulator only; it does not capture cellular call audio.
